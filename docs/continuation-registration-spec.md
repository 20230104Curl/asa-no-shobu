# 小6朝学習｜11月以降の継続利用登録（改修仕様・2026-10-25）

## 基本方針
- 2026-10-31で全体運用終了。2026-11-01 00:00 JST以降は登録完了者のみ利用可能。
- 保護者のメール返信・教員の名簿転記を不要にする。
- 生徒は8桁ID入力→既存名簿から氏名を表示→継続希望確定の3ステップ。
- 既存の生徒ID、氏名、校舎、実施・採点・学習履歴を変更・削除しない。
- 登録者がログインできても、各アプリ固有の問題配信期間・教材日程は別途確認する（11月に問題が提供されるとは限らない）。

## 調査で判明した構造
- 入口: 20230104Curl/asa-no-shobu の index.html（GitHub Pages）
- 一読勝負: Google Apps Script Webアプリへ直接遷移。
- 文脈勝負: 20230104Curl/bunmyaku-shobu（GitHub Pages + GAS + Sheets）。生徒名簿は「生徒名簿」、ID・氏名・校舎・利用状態を保存。verifyStudent と startAttempt に利用状態チェックあり。10月31日までの問題日程。
- 一題勝負: 20230104Curl/ichidai-shobu、Firebase Hostingベース。
- 計算勝負: Google Apps Script Webアプリへ直接遷移。
- アプリの認証基盤は統一されていない。ポータル画面だけを制限しても個別アプリの直リンクから迂回できる。

## 登録ページ
1. 生徒IDを入力し「確認する」を押す。
2. サーバーの名簿を参照し、生徒の氏名（必要なら校舎）を表示。ID未登録は汎用エラー。
3. 「継続利用を登録する」を押す。
4. サーバー側で同じIDの登録を冪等（2回登録しても1件）に処理し、登録完了時刻をJSTで保存。
5. 既登録者は「登録済みです」と表示。

## 共通許可台帳
- 生徒ID（文字列8桁、ユニーク）、継続登録フラグ、登録日時、更新日時、運用者による停止フラグ。
- 氏名・校舎は既存名簿から照会し、重複保持を避ける。
- 登録用APIと利用許可照会APIを共通化する。
- 11月1日以降、各アプリの「ログイン照合・問題取得・開始・保存/提出・再開」のサーバー側入口で許可を判定。
- 時刻は端末の時計ではなくサーバーJSTで判定。未登録/停止の生徒には問題や学習データを渡さない。
- 既存の「利用停止」は継続登録より優先する。
- 11月1日以前は現行機能を維持する。11月1日の切替前に4アプリ全部の接続テストを実施する。
- 登録システム障害時は誤って全員許可しない。管理者は障害を確認・対応できるようにする。

## 個人情報保護・セキュリティ
- 8桁IDと氏名確認だけでは厳密な本人認証にならない点を運用上明記。既存認証方式があれば再利用、必要なら追加の本人確認を導入。
- ID総当たりを防ぐため照会回数制限、アクセス監査、必要最小限の応答、台帳への書込権限制限を導入。
- GitHub Pagesに名簿や許可者ID一覧を公開しない。
- 集計や教師ダッシュボードの過去データは保持する。

## リリース条件
- 正しいID→正しい氏名確認→登録→11月以降の利用が可能
- 未登録者は、4アプリの直リンクを含め利用不可
- 停止者は登録済みでも利用不可
- 既登録の再送信が重複しない
- 10月中は現行学習機能に影響しない
- 11月の各教科の問題の有無と期間設定を別途確認
- 各アプリのサーバー実装と公開を終えるまで保護者へ登録URLを配布しない
